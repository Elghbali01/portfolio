- Regex education sans frontières de mot.
- Extraction de métrique allant jusqu'à la ponctuation au lieu de s'arrêter à une conjonction.
- Certification Backend classée sans héritage du domaine du projet.

18. Limitations restantes
- La notification hors fenêtre doit encore être validée manuellement ou par un test E2E disposant d'interception/délai réseau contrôlé.
- Le libellé des cartes est « View certificate » plutôt que « Verify certificate » ; les liens eux-mêmes sont bien les liens Verify officiels.
- Le planner Groq peut être temporairement limité. Les chemins couverts disposent désormais de fallbacks déterministes, mais une formulation totalement nouvelle peut encore recevoir une erreur localisée si aucun fallback grounded n'existe.
- Les logs de latence sont côté serveur et non corrélés par requestId ; le rapport peut associer les séquences, mais une observabilité production robuste nécessiterait un identifiant anonyme.
- Le rate limiter reste process-local.

19. Verdict final
Prêt pour production : OUI, avec réserve mineure.
Les parcours API critiques, multilingues, conversationnels et anti-hallucination sont stables et les 98 régressions passent. Aucun blocker fonctionnel du chatbot n'est connu.

Points non bloquants à traiter pour considérer la validation UI absolument complète :
1. ajouter un test E2E contrôlant réellement la réponse arrivée après fermeture et le badge unread ;
2. décider si le texte UI doit devenir « Verify certificate » au lieu de « View certificate » ;
3. éventuellement ajouter un requestId anonyme aux logs de latence.
