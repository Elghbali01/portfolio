===== RAPPORT CODEX — AI PORTFOLIO ASSISTANT V3 =====

1. PROBLÈMES IDENTIFIÉS
- Le chatbot ne lisait que les fichiers data, alors que le CV public contenait des faits supplémentaires.
- Les projets n'avaient pas de domaine principal ni de valeur recruteur structurée.
- Les certifications n'avaient pas de domaine, compétences couvertes ou pertinence.
- Le fast path interceptait aussi les questions complexes contenant projects/skills/certifications.
- La détection Darija ignorait plusieurs marqueurs mixtes tels que 3lach et y9der.
- Le modèle 8B sélectionnait souvent les bons éléments mais omettait la justification, et produisait parfois un JSON invalide en français/Darija.

2. POURQUOI CERTAINES INFORMATIONS VISIBLES ÉTAIENT INCONNUES
Le contexte était construit depuis profile.ts, projects.ts, certifications.ts, skills.ts et journey.ts. Le contenu du CV PDF n'était pas structuré dans ces sources. Le CV contient notamment les établissements exacts, l'objectif PFE, l'organisme et la durée du stage, les niveaux linguistiques et deux projets Data Science. En revanche, l'année du bac n'apparaît ni dans le code ni dans le CV.

20. LIMITATIONS RESTANTES
- llama-3.1-8b-instant reste irrégulier pour les justifications et le JSON multilingue ; la couche grounded-reasoning corrige les scénarios recruteur clés.
- Les appels Groq réels testés ont pris environ 10 à 35 secondes selon le cas malgré le modèle instant, probablement en raison du free tier, du contexte et parfois du retry.
- La garantie déterministe couvre les principales candidatures, sélections Backend/Data, certifications, comparaison et technologies non documentées, mais pas toutes les formulations imaginables.
- Le rate limiter reste en mémoire du processus.
- Les deux projets trouvés dans le CV n'ont ni page projet, ni image, ni dépôt GitHub documenté.
